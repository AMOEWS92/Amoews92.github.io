Professional Self-Assessment

Professional Growth

Completing my Bachelor of Science in Computer Science has changed the way I think about software development and the kind of career I want to build. When I started the program, I was mostly focused on learning programming languages and figuring out how to make programs work. As I moved through more advanced courses and larger projects, I began to understand that professional software development involves much more than writing code that produces the correct result. It also involves planning, testing, security, maintainability, communication, collaboration, and understanding how different parts of a system work together.

One of the biggest things I have gained from this program is confidence in my ability to learn unfamiliar technologies. Throughout the degree, I worked with C++, JavaScript, TypeScript, Angular, Node.js, Express, MongoDB, REST APIs, OpenGL, Unreal Engine, Android development, and artificial intelligence concepts. I did not begin the program already knowing how to use all of these tools. Each course required me to build on what I already knew and then learn something new. That experience has prepared me for a field where technologies will continue to change and where learning will always be part of the job.

My immediate professional goal is to begin working in software development or software engineering. I am especially interested in full-stack development because I enjoy understanding how the different pieces of an application connect. My longer-term interests also include game development and interactive software.

Collaboration and Communication

Collaboration has been an important part of my growth. One of my strongest team experiences came from working on a game development project in Unreal Engine. I served as a team lead and producer while also contributing to the user interface and user experience portions of the project. Our team had to divide responsibilities, communicate about progress, troubleshoot problems, manage files through GitHub, and integrate work created by multiple people.

That experience was valuable because not everything went according to plan. We dealt with source control problems, Unreal Engine asset issues, file synchronization problems, and differences in how quickly team members were able to complete their work. Those challenges taught me that teamwork in software development is not just about dividing a project into separate pieces. A team needs consistent communication, clear expectations, realistic planning, and the ability to adjust when something does not work as expected.

The program also helped me become more comfortable communicating technical information to different audiences. Throughout my coursework, I created project plans, testing documentation, presentations, code reviews, and technical explanations. During the capstone, the code review required me to explain how my existing projects worked, identify weaknesses, and describe how I planned to improve them.

Algorithms and Data Structures

My understanding of algorithms and data structures has grown throughout the program. Earlier in my coursework, I tended to think mainly about whether a program produced the correct result. Over time, I learned to think more carefully about how information is stored, how it is processed, and why one solution may be more appropriate than another.

My enhanced Left Center Right Dice Game is a good example of that growth. The original version focused mainly on simulating one game. During the capstone, I expanded it into a tournament system that tracks games played, wins, chips won, and leaderboard rankings. I used vectors, an unordered map, structured game results, reusable functions, and custom sorting logic to organize and process the tournament data.

I also worked with algorithms in different contexts during the program. In an artificial intelligence course, I worked with a reinforcement learning agent that learned how to navigate toward a goal. That project showed me that algorithms can be applied to much more than traditional sorting or searching problems.

Software Engineering

Software engineering became one of the areas where I saw the most growth in my own work. Travlr Getaways originally taught me how the pieces of a full-stack application connect. The application uses Angular for the administrative interface, Express and Node.js for the server and API, MongoDB for data storage, and Mongoose for working with the database.

When I returned to the project during the capstone, I could see areas that I would have approached differently if I were building it with the knowledge I have now. I improved validation, error handling, administrative workflows, reusable functionality, and the communication between the Angular frontend and Express backend.

Other projects also helped expand the way I think about software engineering. My OpenGL work required me to think about graphics, transformations, textures, lighting, and three-dimensional scenes. My Unreal Engine projects required me to combine gameplay systems, animation, user interfaces, level design, input, and testing.

Databases

Database development became another major part of my technical foundation. Through MongoDB projects and Travlr Getaways, I learned that databases are much more than storage. The way information is structured and validated has a direct effect on the rest of the application.

For my database enhancement, I strengthened the Mongoose schema validation and added MongoDB aggregation reporting. The application can now calculate the total number of trips, average trip price, average duration, and the number of trips grouped by resort. Those results are generated through MongoDB, passed through the Express API, and displayed in an Angular Trip Report interface.

One challenge I encountered was that some of the original data had been designed more for display than analysis. Prices and durations were stored as formatted strings, which meant they had to be converted during aggregation. Working through that problem made me think more carefully about database design.

Security

Security has also become something I think about earlier in the development process. Travlr Getaways uses JSON Web Tokens to protect administrative functionality, and the validation improvements help protect the integrity of data entering the application. I have also learned to keep secrets and configuration values in environment variables rather than storing credentials directly in source code.

Preparing my projects for a public GitHub portfolio reinforced this even further. I had to think about what should and should not be committed to a public repository. Files such as environment files, dependencies, build artifacts, and generated development files do not belong in a professional public repository.

Building this ePortfolio has helped me see my progress more clearly. When I originally created these projects, I was focused mainly on completing the requirements and learning the technology. Returning to them later allowed me to look at them from a more experienced perspective. I could see where the structure could be cleaner, where validation was missing, where functionality could be expanded, and where the code could better reflect professional development practices.

The three artifact enhancements in this portfolio represent different parts of that growth. Together, these projects show that I am comfortable working across different languages and areas of computer science. More importantly, they show that I can look at an existing problem, understand how the current solution works, identify areas that can be improved, and build a better version.

I am leaving the program prepared to pursue an entry-level role in software development or software engineering while continuing to build toward my longer-term interests in game development and interactive applications. This portfolio represents the work that helped me build those skills and the foundation I will continue developing throughout my career.

Software Design and Engineering Enhancement Narrative

Artifact Description

Travlr Getaways is a full-stack web application built using the MEAN stack: MongoDB, Express, Angular, and Node.js. The application allows users to browse travel destinations while providing an administrative interface where authenticated users can create, edit, update, and delete trip information.

The project demonstrates full-stack web development, RESTful API integration, database management, and authenticated administrative functionality.

Justification for Inclusion

I selected Travlr Getaways because it demonstrates several software engineering concepts that are important in professional development environments. The application combines front-end development with Angular, server-side programming with Express and Node.js, MongoDB data storage, and JWT authentication.

For this enhancement, I focused on improving the Edit Trip workflow. The original implementation provided basic editing capabilities but limited validation and user feedback.

I improved the application by implementing stronger form validation using Angular Reactive Forms, adding custom validation for currency values, applying minimum and maximum character limits, displaying loading indicators while trip data is retrieved, disabling the Save button during update operations, and providing clear success and error messages after update attempts.

These changes improved reliability and usability while also making the application easier to maintain and extend.

Skills and Course Outcomes

The enhancement demonstrates the use of modern software engineering practices to improve an existing full-stack application.

The strongest alignment is with the outcome involving the use of well-founded computing techniques and tools to deliver value. Angular Reactive Forms, improved validation, better user feedback, and more reliable update behavior all strengthened the quality of the application while preserving its existing architecture.

The enhancement also supports a security-focused development mindset. Client-side validation, improved error handling, and authenticated update operations reduce the likelihood that invalid data will enter the system. These changes reinforced the importance of considering usability and security together rather than treating them as separate concerns.

The project also demonstrates professional communication through the user interface itself. Loading indicators, validation messages, confirmation messages, and error responses provide users with clear information about what the application is doing and whether their actions were successful.

Reflection

Enhancing Travlr Getaways gave me valuable experience working within an existing full-stack application rather than creating a project from the beginning.

One of the most important lessons from the enhancement was understanding how closely the different application layers depend on one another. Implementing the changes required modifications to Angular components, HTML templates, Express routing, backend controllers, and database interactions while ensuring that communication between each layer continued to work correctly.

One of the greatest challenges involved troubleshooting problems that prevented trip data from loading correctly. Resolving these issues required tracing requests through the Angular application, Express routes, backend controllers, and MongoDB queries until inconsistencies in route parameters were identified and corrected.

I also encountered challenges with form validation behavior and ensuring that user feedback appeared correctly after successful updates. Working through these issues reinforced the importance of systematic debugging, careful testing, and verifying communication across the entire application stack.

Overall, the enhancement improved both the quality of the application and my understanding of professional software engineering practices. Rather than simply adding new features, I focused on maintainability, usability, validation, and reliability while preserving the application's existing architecture.

This experience strengthened my confidence in developing and maintaining full-stack applications and showed me how thoughtful software improvements can improve both the user experience and the overall quality of a software system.
